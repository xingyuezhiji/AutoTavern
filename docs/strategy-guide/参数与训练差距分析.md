# 扩容有价值，训练量也需要补齐

你在启智任务 917730 里训练的策略模型有 2,992,951 个参数，约 299 万。论文的 TavernAgent 约 1800 万参数，容量约为你的 6 倍。参数偏少可能限制能力，但目前还不能据此认定它是主要瓶颈。

来源：[TavernAgent 原论文](https://arxiv.org/html/2610.33845v1)、用户提供的《分析论文模型训练细节》、917730 和 917395 的实际权重与训练记录。

## 论文的扩容实验支持继续试大模型

论文第 6 节的同预算实验如下。各模型在同一评测环境比较，不能把这里的名次直接和我们对脚本机器人的结果比较。

| 参数量 | 平均名次 | 前四率 |
|---|---:|---:|
| 350 万 | 3.84 | 73.9% |
| 800 万 | 3.77 | 75.6% |
| 1800 万 | 3.67 | 78.5% |

从 350 万扩大到 1800 万，平均名次改善 0.17，前四率提高 4.6 个百分点。因此，扩容值得验证。论文使用的是实体 Transformer：卡牌和对手分别编码成 token，再通过注意力建模关系。我们现有模型主要通过 MLP 处理整体特征，卡牌 embedding 做池化，并叠加动作身份头。仅扩大 MLP 的宽度，无法等价复现论文结构。

## 训练数据的差距比参数倍数更大

论文附录 C 给出的最终阶段配置是每阶段 300 次 PPO 迭代，每次约 105 万次决策；一阶段约 3.1 亿次决策、57 万场对局。

| 训练记录 | PPO 轮数 | 学习者对局 | 决策数 |
|---|---:|---:|---:|
| 你的任务 917730 | 40 | 1280 | 226,309 |
| 你的任务 917395 | 200 | 25,600 | 4,297,342 |
| 论文一个最终阶段 | 300 | 约 570,000 | 约 310,000,000 |

论文一个阶段的决策量，约为 917730 的 1370 倍、917395 的 72 倍。因此，轮数相近不代表训练量相近。模型扩大后仍然只给很少的经验，也可能学不好。

论文使用 PPO、γ=1、GAE λ=0.995，更新 batch 为 8192，更新 epoch 为 1；阶段前 100 次迭代加入系数 0.1 的阶段初始策略 KL 约束。论文没有描述先用行为克隆预训练的流程。

附录 F 的主线算力为 8 张 H200、128 个 CPU 核，23 个交付阶段累计约 1900 GPU 小时。20 天是包含开发和实验的项目周期，不能理解为单个模型的一次训练时长。

## 更强的对手会暴露现有模型的差距

使用相同的新种子 20601030，对 917395 和 917730 做完整对局测试，并轮换学习者座位：

| 模型 | 对手 | 场数 | 平均名次 | 前四率 |
|---|---|---:|---:|---:|
| 917395 | 7 个脚本机器人 | 128 | 3.609 | 68.0% |
| 917730 | 7 个脚本机器人 | 128 | 3.453 | 71.9% |
| 917395 | 3 个历史模型＋4 个机器人 | 64 | 3.078 | 78.1% |
| 917730 | 3 个历史模型＋4 个机器人 | 64 | 3.203 | 79.7% |
| 917395 | 7 个历史模型 | 64 | 3.875 | 57.8% |
| 917730 | 7 个历史模型 | 64 | 4.000 | 57.8% |

样本还不足以证明两个模型谁整体更好，但 917730 面对全历史模型对手时，前四率明显低于机器人场。混合对手场的平均名次也不一定介于另外两场之间，因为所有对手都会相互影响，不能只按单个对手强度推断难度。

论文采用真人强度校准的对手阵容库。同权重、同预算的消融实验中，校准后吃鸡率从 20.9% 提高到 27.2%。我们这轮加入历史模型对手，还没有真人阵容库，不能称为复现了论文的对手校准。

## 已提交扩容实验与历史对手训练

原 A100 任务 918038 已停止。按用户要求，替换任务使用天数智芯 BI-V100：32 GiB 显存、30 核 CPU、64 GiB 内存，平台报价为 1 积分/小时。保留 917730 起始权重与 120 轮历史对手 PPO 配置。

任务 918043 和 918045 在 CoreX 3.2.0＋PyTorch 2.1 镜像中均卡在第一次显存分配，分别使用了禁用缓存和原生缓存配置，均未开始模型训练。任务 918047 尝试平台列出的 CoreX 3.1.1 镜像，但平台返回“image not available”，没有启动容器。任务 918048 将初始化检查延长到 180 秒后仍在同一位置超时。资源标价不等于最终扣费金额。

用户进一步授权尝试沐曦 GPGPU。C500 使用 64 GiB 显存、20 核 CPU、50 GiB 内存，标价 2 积分/小时，镜像为 MACA＋PyTorch 2.8＋Python 3.12。任务 918049 通过显存分配检查后卡在 Rust 下载，已停止；任务 918059 的预训练模型挂载没有提供校验通过的模拟器安装包，启动检查失败。

[任务 918065](https://openi.pcl.ac.cn/cloudbrains/detail/918065) 随代码附带已校验的 Linux 模拟器安装包，启动时验证 SHA256 和源码指纹，保留厂商适配的 PyTorch、NumPy。实际设备为 MetaX C500。MLP 的前向、反向与优化器检查已通过，小、大两档 Transformer 均已验证 GPU 参数变化。任务完成 3 轮 PPO，随后历史对手的动作执行遇到“a choice is pending”错误。120 轮 PPO 与容量对比结果尚未完成。

历史对手批量决策等待执行期间，其他座位可能改变其可见状态。已在执行前核对当前观察和合法动作，状态变化时重新决策。修复后通过 3 组种子的 192 场完整对局；验证仅做 CPU 推理，没有参数训练。重试继续使用已通过 GPU 更新检查的 MACA 镜像。

每轮 64 场完整学习者对局，对手按机器人、混合历史模型、全历史模型组成课程。更新加入 GAE 与阶段初始策略 KL 约束，用独立的开发种子选择权重，并限制机器人场性能退化。正式训练前验证两档 Transformer 能在所选 GPGPU 上执行前向、反向及参数更新；不使用 CPU 训练，也不自动切回英伟达 GPU。

容量实验单独保存两个实体 Transformer：

| 模型 | 参数量 | 结构 |
|---|---:|---|
| 小模型 | 3,035,303 | 4 层，6 头，隐藏维度 168 |
| 大模型 | 18,669,911 | 8 层，8 头，隐藏维度 384 |

两者使用相同的 57 token 编码、攻略样本、按对局划分的数据集、蒸馏教师、batch 顺序、优化器与 8 轮训练，再用相同的新种子分别评测。它们包含卡牌 ID 和可见数值特征，没有论文的预训练规则文本 embedding。

这项容量实验检验的是小预算下的蒸馏初始化效果；两个学生模型还没有做同预算 PPO，不能据此确定长期强化学习的最佳参数量。任务完成前也不能声称大模型已经更强。现有 MLP 和初始权重会保留，最终报告将列出独立评测与不确定区间。
