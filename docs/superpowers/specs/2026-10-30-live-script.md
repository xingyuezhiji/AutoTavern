# 模型驱动的酒馆战棋客户端脚本

用户已要求实现脚本，并补充了四个参考项目。本次直接实现，不另设设计审批。

## 运行方式

在 Windows 上读取官方客户端的 Power.log，以本地 PyTorch 权重选动作，通过前台窗口鼠标操作执行。默认只输出建议；执行模式由启动参数开启。用户自行进入对局，脚本不负责匹配或重开比赛。Mac 支持日志回放、模型推理和动作计划验证。

## 状态与模型

使用当前训练代码的模型类，支持 MLP、action identity 和 entity Transformer。输入布局保持 4017 floats、447 card indices、245 actions。卡牌顺序来自训练仓库的 cards.json，未知卡牌必须拒绝，不能映射成空卡。日志解析独立实现，不复制第三方源代码。

完整模拟器 JSON 回放复用原生 observe2，作为精确参考。正式客户端日志能恢复核心可见状态，但不能保证恢复全部脚本计数、附加效果和对手历史摘要。日志模式必须显式报告这类缺失；默认只建议，试运行需显式接受估计上下文。核心状态、合法选项、站位或目标缺失时，即使试运行也不得操作。不能把日志近似编码宣称为完整训练状态。

## 执行动作

对应全部 245 个动作编号，映射买入、卖出、刷新、冻结、升级、英雄技能、黑暗之赐、取消、选择、出牌、磁力和移动。选择目标时使用实体的区域与位置，不把目标当作发现面板按钮。没有映射或校准的动作从可执行 mask 中排除。

一次只执行一个模型动作。执行前检查日志版本、前台窗口、客户端尺寸；执行后等待状态或选项变化，超时停止，不重复点击。F8、Ctrl+C、停止文件均可退出。日志截断、轮换和新对局必须清空历史状态。窗口坐标以客户端区域为准，使用归一化校准，允许手牌弧形布局单独配置。

## 验收

离线检查覆盖真实格式的日志、跨块标签、选项与目标、站位变化、版本保护、完整模型推理和原生编码参考。输出 Windows 启动脚本、配置、操作说明和离线验证结果。正式客户端没有在当前 Mac 上实测，文档必须保留这一限制。
