# 酒馆桌面脚本 V2

用户要求参考 [HsBgAI](https://github.com/kanshufan-1107/HsBgAI)，交付新的 Mac 和 Windows 版本。新增独立的 `desktop_tavern` 入口、配置和安装包，旧 `live_tavern` 入口继续可用。

## 参考结论

参考版本为 `997910c3962490513626948241fdbdb0bd39b4cd`。HsBgAI 以 BepInEx 5、net48 和游戏程序集调用为基础，仅声明支持 Windows。其状态机覆盖找局、英雄选择、招募、战斗及结算。招募策略按升级、购买、满场出售、出牌、刷新、技能的固定顺序逐项尝试；英雄和一般发现参考本地 Firestone 统计文件。

新版独立编写，采用状态机、统计缓存和逐动作确认的设计，继续通过本地训练权重决定招募动作。参考项目的 C# 源码、DLL 和数据不复制进 MIT 项目，也不将其 Windows 插件声明为 Mac 插件。

## 新版行为

- 将大厅、排队、英雄选择、招募、一般发现、战斗、结算、等待、停止、错误表示为明确阶段，阶段变化输出结构化记录。
- Power.log 负责游戏、玩家、合法选项、英雄选择和阶段的证据。英雄使用 `ChoiceType=MULLIGAN`、本地控制者和实际 `ZONE_POSITION`，过滤 `BACON_LOCKED_MULLIGAN_HERO`；发现与英雄选择区分处理。
- 招募与一般发现继续使用 4017 / 447 / 245 的模型接口、卡库指纹和合法动作掩码。核心信息缺失时等待；不以固定升级曲线替代模型，也不把未知卡当空卡。
- 英雄统计支持用户提供的本地文件，按平均名次排序，允许用基础 DBF 编号匹配皮肤。统计无可用项时明确记录回退依据，例如可选英雄的护甲，不伪造胜率。
- 新增游戏外界面的局部截图模板校准。大厅、排队、结算与英雄确认仅在用户采集的模板匹配时使用；模板不存在、多个场景同时匹配或窗口尺寸变化时不点击。默认不开自动找局和结算点击，配置后执行模式可串联下一局。
- 每次动作都核验窗口、状态和版本，一次执行一个计划，再等待特定确认。找局只在确认排队或新游戏后继续；英雄选择先选卡，再等待确认界面的证据；招募等待 SendOption / SendChoices 及新状态。超时停止，不盲目重试。
- 增加每回合动作上限、单次运行对局上限、进程互斥、持久 STOP、F8 / Ctrl+C 和鼠标释放。记录每局的阶段、动作和局面快照，供后续验收与数据处理。

## 平台和交付

Mac 使用 Quartz / AppKit 的逻辑点坐标，Windows 使用前台客户区及 DPI 坐标；复用已有底层执行器。截图必须按同一窗口坐标映射，处理 Retina 的截图分辨率差异。Mac 安装默认支持已验证的 Apple Silicon，Intel 的 PyTorch 二进制依赖限制写入说明。

分别提供 Mac `.command` 和 Windows `.cmd` 安装、启动、检查、校准、停止和重置入口。两份 ZIP 都包含独立源码、917730 权重、合成回放样例、配置、说明和验证报告。训练代码和模型类共用，配置不共用。

## 验收边界

离线验收包括英雄锁定与物理槽位、皮肤统计匹配、阶段切换、动作确认与超时、场景模板歧义、重复找局防护、并发锁、停止控制、跨平台输入模拟、真实权重回放和解压独立运行。

不在本次运行中进入真实天梯或发送真实桌面动作。当前 Mac 没有安装炉石，Windows 也没有运行环境；报告明确区分模拟检查、Mac 只读诊断和真实游戏未验收。无法从日志或模板确认的 UI 流程写明限制，不将离线通过当成实战效果。
